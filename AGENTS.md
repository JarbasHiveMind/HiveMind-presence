# AGENTS.md — `HiveMind-presence`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

Local-network presence and discovery for the [HiveMind](https://github.com/JarbasHiveMind)
ecosystem — a hub node announces itself on the LAN (`hivemind-presence announce`)
so a satellite can find it without being told its IP, and a satellite scans the
LAN (`hivemind-presence scan`, or the `LocalDiscovery` API) to locate reachable
hubs and open a connection. It sits next to
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core) (the hub) and
the client libraries that actually speak the wire protocol once a node is found;
this package only solves "where is the hub", never the handshake itself.
Discovery transports today are mDNS/Zeroconf (optional, LGPL, imported lazily)
and UPnP/SSDP (being retired). The roadmap moves the default transport to
HiveBeacon, a zero-dependency UDP broadcast beacon absorbed from the archived
`HiveBeacon` project.

## Layout / build / test

- Package module: `hivemind_presence/` (`presence.py` announce side,
  `discovery.py` scan side, `zero.py`/`ssdp.py`/`upnp_server.py` per-transport
  implementations, `scripts.py` the CLI entry point). Tests live in `tests/unit/`
  and `tests/e2e/` — do not create a second test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`. `tests/e2e/`
  drives a real advertise↔discover round trip over loopback/LAN multicast
  zeroconf (nothing mocked); the UPnP/SSDP e2e case is skipped by design because
  M-SEARCH multicast is unreliable in sandboxed CI runners. `conftest.py` loads
  `hivescope.pytest_fixtures` unconditionally, so a missing `[test]` install
  fails loudly instead of silently skipping the e2e suite.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev`. A human merges. You do not merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the maintainer's
  stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits; `feat:`
  only for a user-visible new capability. `fix:`, `docs:`, `chore:`, `ci:`
  otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries, at
  the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT human-reviewed.
  Verify before acting.` PR bodies are plain human prose (3–6 short paragraphs),
  no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a comment
  instead; on your own PRs, edit the body rather than piling on comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and standalone:
  no dates, no "currently/now/new", no meta-commentary about the edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, `.egg-info`,
  or build artifacts in a PR. `git show --stat` shows only intended files.
- **Keeping this AGENTS.md current is a quality gate.** Any PR that changes this
  repo's conventions, build/test commands, dependencies, entry points, or
  observable behavior updates AGENTS.md in the same PR. A stale AGENTS.md is a
  review-blocking defect, the same tier as a failing test.

## Dependencies

- **Floor pins only** (`>=X.Y.Za1`), bumped when a feature or fix is actually
  needed — with a one-line comment saying why. No upper caps unless a specific
  released version is genuinely broken (say which and why); the one exception
  already in `pyproject.toml`, `ovos-bus-client<3.0.0` in the `[test]` extra, is
  a real cap, not a floor — leave it as-is unless the test suite is being
  ported to the 3.x line on purpose.
- **No lockfiles, ever.** Target the latest alphas (`--prerelease=allow`).
- Everything in `pyproject.toml` (deps, metadata, version). Never install from
  git — depend on a published PyPI alpha.
- This repo is **MIT-licensed**, not Apache-2.0 (check `LICENSE` before assuming
  otherwise). Do not add GPL/AGPL dependencies as hard requirements; `zeroconf`
  is LGPL and stays optional and lazily imported for that reason — keep it that
  way for any future optional transport too.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing; the `[test]`
  extra pins `zeroconf` precisely so the mDNS e2e path is never silently
  skipped in CI.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This is infra, not a wire-protocol implementation: it never speaks the
  HiveMind bus protocol itself, only advertises/discovers connection
  parameters (host, port, name, TLS flag) so a client can then hand off to
  `hivemind_bus_client`. Do not fold protocol/auth logic in here — that belongs
  in the client library.
- `LocalDiscovery` raises if both transports are disabled; keep that fail-loud
  behavior when adding a transport rather than silently returning no results.
- The mDNS fallback in `presence.py`/`discovery.py` (silently reducing to UPnP
  only when `zeroconf` is not installed) is documented, deliberate behavior —
  do not "fix" it into a hard import error without discussing it first, since
  the optional-dependency contract is part of the public API surface.
- When adding the planned HiveBeacon UDP-broadcast transport, keep it a
  zero-dependency addition (that is the point of absorbing it from the
  archived `HiveBeacon` project) and keep mDNS/UPnP working as siblings, not
  replaced, until the migration is explicitly decided.
- Advertised data (name, host, port) is not a credential and is not currently
  authenticated at the discovery layer — do not assume `scan()` results are
  trustworthy without the downstream key/crypto-key handshake; do not add a
  false sense of security by silently trusting an unauthenticated node.
